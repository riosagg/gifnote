# GIFnote

動画・GIFの好きな区間を切り出し、noteの記事に掲載しやすいGIFを作る、完全クライアントサイドのWebツールです。noteの公式サービスではありません。

ユーザーによるnoteへの手動挿入テストは、下記の実機テスト結果に記録しています。

## ローカル起動

Node.js **22.12以上**（実装時は22.21.0）、npmが必要です。

```powershell
cd GIFnote
npm install
npm run dev
```

ブラウザで <http://127.0.0.1:5173/> を開きます。終了するときは、起動したターミナルで `Ctrl+C` を押します。

PowerShellで `npm.ps1` の実行が制限されている場合は `npm.cmd install`、`npm.cmd run dev` としてください。5173番ポートが使用中の場合は、既存のサーバーを停止するか `npm run dev -- --port 5174` を使用します。

```powershell
npm run typecheck
npm run build
npm run preview
```

`build` はTypeScriptチェック後、`dist/` に静的サイトを生成します。`preview` は <http://127.0.0.1:4173/> で生成結果を配信します。`index.html` の直接ダブルクリックでは動作しません。HTTPサーバーから開いてください。

初回の `npm install` はnpmレジストリから依存関係をダウンロードします。npmキャッシュもプロジェクト内の `.npm-cache/` に保存します。アプリの使用時に入力動画・GIFを外部へ送信する機能はありません。

## 使い方

1. MP4・WebM・MOV・GIFをドロップ、またはファイル選択で開く。
2. 開始・終了スライダーまたは秒数入力で、好きな場所から最大15秒を選ぶ。
3. 必要なら「自由」「16:9」「4:3」「1:1」で画角を指定する。
4. 「note用GIFを作る」を押す。
5. 完成プレビュー・容量を確認し「GIFを保存」を押す。

開始・終了を動かして15秒を超える場合は、反対側の位置が自動で追従します。原則最短1秒ですが、1秒未満の元ファイルは全長を選択できます。再生位置スライダーは入力全体の確認用です。「選択範囲を再生」は選択区間を音声なしで繰り返します。

スライダーの表示範囲は、素材の先頭0秒から末尾までです。最大15秒は選択区間の長さだけの制限であり、タイムライン全体の上限ではありません。開始・終了のドラッグは原則0.1秒刻みで、4.84秒など端数のある末尾は正確な終了位置を保持します。矢印キーは0.1秒移動、スライダーのHome/Endキーは先頭/末尾へ移動します（最短・最長の選択区間制限は適用されます）。数値欄の上下キーも0.1秒ずつ調整できます。

トリミング枠は内部ドラッグで移動、四隅・四辺でサイズ変更できます。タッチ操作にも対応しています。枠にキーボードフォーカスを合わせると、矢印キーで移動、Shift＋矢印キーでサイズ変更できます。

## 容量と標準値

`src/config.ts` の `NOTE_GIF_CONFIG` が標準値の管理箇所です。仕様書の値として最大15秒・620px・10fps・20 MB未満を採用しており、note側の最新の掲載条件を確認したという意味ではありません。

1 MB = 1,000,000 bytesで計算します。15 MB以下を目標に、20 MB**未満**を必須条件にします。20 MB未満に入った後は追加の軽量化を最大1回に抑え、大幅な品質低下を避けます。設定上限を超える結果には保存ボタンを出しません。全段階で上限を満たせない場合は、区間短縮・トリミングを案内します。

手動の横幅・FPS・色数は最初の変換設定です。容量調整時は自動的に下がることがあります。GIFの時間精度は1/100秒のため、7fpsなどでは各フレーム時間に丸めが生じます。結果には実データから計算した平均FPSを表示します。

### 終了スライダーの修正

以前は `step="0.1"` のrangeに4.84秒を設定すると、ブラウザが有効な刻みの4.8秒へ丸め、数値欄の4.84秒とつまみ位置が一致しませんでした。また、rangeへ値を反映する際に小数第3位へ丸めていたため、素材の正確なdurationとのずれが生じ得ました。`max` 自体は素材のdurationを使っており、15秒制限との混同やthumb位置を変えるCSSはありませんでした。

rangeを `step="any"` に変更し、両端の値とrange表示には正確なdurationを使います。途中のドラッグの0.1秒刻みとキーボード操作はアプリ側で処理し、数値欄も端数を受け付けます。数値欄は浮動小数点の誤差を見せないよう最大小数6桁で表示し、表示上の末尾時刻を入力した場合は元の正確なdurationへ戻します。CSSでの位置補正は行っていません。

4.84秒から4.8秒への丸めによる差は全長の約0.83%です。報告された「かなり手前」という大きな見た目のずれはローカルの値計算だけでは再現していないため、修正後のブラウザ表示で追加確認が必要です。

**この修正後のブラウザ上の見た目・操作はユーザーによる最終確認待ちです。** 下記の実機テストは、今回のスライダー修正前にユーザーが確認した結果です。すべての素材・端末での動作やGitHub Pagesでの動作を確認したものではありません。

## 制限・既知の注意点

- **基本のGIF・動画変換とnoteへの挿入はユーザー実機確認済み**です。ただし、今回のスライダー修正後の表示・操作、未確認の比率や境界ケース、各ブラウザ・iOS/Androidのメモリ制限は追加確認が必要です。
- 単一スレッドのWASMを採用しているため、大きな入力や長いGIFの変換は時間がかかります。1回のFFmpeg処理は最大15分で打ち切ります。予想完了時刻は表示しません。
- 入力の全ファイルは変換時にWASMのメモリへ読み込みます。4K、特に縦長素材は負荷が高く、端末によって失敗することがあります。150 MB以上・4K相当以上・10分以上に注意を表示し、750 MB超または4,000万画素超は保護のため受け付けません。
- 長いGIFを後ろからシークすると、正しい合成のため前のフレームから再描画することがあります。全フレームの展開画像を保持しない設計なので、位置変更後の表示に時間がかかる場合があります。
- 対応拡張子でもコーデック・破損状態によって読めない場合があります。ブラウザが直接読めない動画の代替プレビューは、動画全体を低解像度に変換するため時間・メモリを使います。特殊な非正方形ピクセルや任意角度の回転を持つ素材では見た目の一致を要確認です。
- 透過GIFの半透明はGIF形式の仕様上表現できません。フレーム間隔より短い素材は少なくとも1フレームを出力するため、元より少し長くなる場合があります。特殊なフレーム遅延・disposalを持つGIFは実データで要確認です。
- ファイルは端末内で処理しますが、ページ再読み込み時は編集内容や結果を復元しません。保存前に閉じると結果は失われます。
- すべての圧縮段階を試しても上限未満にできなければ、区間短縮を案内します。あらゆる素材を必ず上限内にできる保証はありません。

## 将来の静的ホスティング

Viteの `base: './'` により、ルート配信とGitHub Pagesのリポジトリ配下の両方を想定しています。`dist/` 全体（`assets/`、`ffmpeg/`、`license/`、`licenses/`、`source/`、`third_party_source/` を含む）を静的配信する構成です。外部CDNへの実行時依存はありません。

`@ffmpeg/core` の**単一スレッド版**を使用し、マルチスレッド版に必要なSharedArrayBufferやCOOP/COEPヘッダーに依存しない構成にしています。公開後のパス・MIME・Worker読み込みの実機確認は必要です。今回は公開設定やワークフローファイルを作成していません。

実装参考: [ffmpeg.wasm公式Usage](https://ffmpegwasm.netlify.app/docs/getting-started/usage/)、[gifuct-js](https://github.com/matt-way/gifuct-js)。

外部の上流リンクもHTTP確認する場合は `npm run licenses:verify:http -- --check-external` を使用します。通常のビルドでは外部ネットワークに依存しません。外部リンクの取得失敗も、この明示的な検証では失敗扱いになります。

## 時間範囲の移動・ファイル取り消し

緑の選択枠を左右にドラッグすると、選択時間の長さを保ったまま範囲全体が移動します。
枠にフォーカスした状態で左右矢印キー（0.1秒）、Home/Endでも移動できます。
開始・終了のシークバーと数値入力は引き続き個別に使えます。ドラッグ中はプレビューを止め、移動後の開始位置を表示します。
「別のファイルを選ぶ」の隣の「取り消し」で読み込みを解除し、Drop Zoneへ戻ります。
入力・出力URL、プレビュー、時間、画角・比率、出力設定、結果、エラー・進捗を初期化します。
ファイルinputも空にするため、同じファイルを再選択できます。FFmpeg Workerの終了により仮想FS・WASMメモリを解放します。

GIFの時間は1/100秒単位です。core 0.12.10では8fps・15秒指定が、最終フレームの表示時間により15.01秒になることを再現しました。
変換要求は最大15.000秒で制限し、各出力GIFの実フレーム時間を整数tickで集計します。
必要な場合だけ末尾の表示時間を短縮・余分な末尾フレームを除去し、選択時間（1/100秒未満切り捨て）以下に収めます。
0/1 tickの遅延はブラウザで長く解釈されるため作らず、その場合は末尾フレームを落とします。
短いGIFを15秒に引き伸ばす処理や、表示だけの丸めではありません。

```sh
npm test
npm run typecheck
npm run build
```

自動テストは範囲移動Case A〜D・端の制限・小数duration、Pointer Eventsと数値/再生位置同期、
動画→取り消し→GIFドロップ、同じGIF再選択、別ファイルへの変更、URL/結果/画角のリセット、
取り消した読み込みの遅延完了を確認します。UIテストはDOM・メディアイベントの代替環境を使います。
実際のcoreと変換処理で、動画/GIF入力それぞれ5/6/7/8/10fps、15秒と14.37秒の計20パターンを生成し、
GIF再解析とffprobeで実時間の上限を確認します。テスト用素材はメモリ内で生成し、公開物に含めません。
既存のライセンス回帰テストもnpm testに含みます。
ブラウザ実機でのドラッグの手触り・タッチ操作・同一ファイル選択のネイティブイベント・noteへの挿入は、変更後の手動確認項目です。
